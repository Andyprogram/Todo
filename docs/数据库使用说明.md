# 数据库使用说明

## 用的是什么数据库？

这个项目用的是 **SQLite**，通过一个叫 `better-sqlite3` 的 npm 包来操作。SQLite 不是那种需要安装服务器的数据库（比如 MySQL），它就是一个**单文件数据库**——所有数据都存到一个 `.db` 文件里，就像你把 Excel 表格存到一个文件里一样。

## 数据存在哪里？

关键代码在 `electron/database.ts` 第 10 行：

```typescript
const dbPath = path.join(app.getPath('userData'), 'todo.db');
```

`app.getPath('userData')` 是 Electron 提供的用户数据目录，不同系统的路径不同：

| 系统 | 路径 |
|------|------|
| **Windows** | `C:\Users\你的用户名\AppData\Roaming\Todo\` |
| **macOS** | `~/Library/Application Support/Todo/` |
| **Linux** | `~/.config/Todo/` |

数据库文件就叫 **`todo.db`**，在这个目录下。你可以用任何 SQLite 工具打开查看。

## 数据库里有什么表？

项目自动创建了 **4 张表**（`electron/database.ts` 第 22-75 行）：

```
┌──────────────────────────────────────────────────────┐
│                     todo.db                          │
├───────────────┬──────────────┬───────────┬──────────┤
│  task_lists   │    tasks     │   steps   │ settings │
│  (任务列表)    │   (任务)     │  (子步骤)  │ (设置)   │
├───────────────┼──────────────┼───────────┼──────────┤
│ id            │ id           │ id        │ key      │
│ name          │ list_id ← FK │ task_id←FK│ value    │
│ color         │ title        │ title     │ updated  │
│ icon          │ note         │ completed │          │
│ position      │ due_date     │ position  │          │
│ created_at    │ important    │ created   │          │
│ updated_at    │ completed    │ updated   │          │
└───────────────┴──────────────┴───────────┴──────────┘
                          ↑
                    外键关联，删除列表时自动删任务
                    删除任务时自动删子步骤
```

**表之间的关系很简单**：一个任务列表里有多个任务，一个任务里可以有多个子步骤。就像文件夹 → 文件 → 清单项一样。

## 数据库结构详解

### task_lists（任务列表）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | UUID 主键 |
| name | TEXT | 列表名称 |
| color | TEXT | 颜色标记，默认 `#3b82f6`（蓝色） |
| icon | TEXT | 图标 emoji，默认 📋 |
| position | INTEGER | 排序位置 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

### tasks（任务）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | UUID 主键 |
| list_id | TEXT | 所属列表 ID（外键） |
| title | TEXT | 任务标题 |
| note | TEXT | 备注详情 |
| due_date | TEXT | 到期日期 |
| reminder_date | TEXT | 提醒时间 |
| is_important | INTEGER | 是否重要（0/1） |
| is_completed | INTEGER | 是否已完成（0/1） |
| completed_at | TEXT | 完成时间 |
| position | INTEGER | 排序位置 |
| repeat_type | TEXT | 重复类型（daily/weekly/monthly/yearly） |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

### steps（子步骤）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT | UUID 主键 |
| task_id | TEXT | 所属任务 ID（外键） |
| title | TEXT | 步骤标题 |
| is_completed | INTEGER | 是否已完成（0/1） |
| position | INTEGER | 排序位置 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

### settings（设置）
| 字段 | 类型 | 说明 |
|------|------|------|
| key | TEXT | 设置键名（主键） |
| value | TEXT | 设置值 |
| updated_at | TEXT | 更新时间 |

默认会初始化一条设置：`theme = 'light'`。

## 前端怎么访问数据库？（重点）

这里有一个新手容易困惑的设计——**渲染进程（前端页面）不能直接访问数据库**。

整个流程是这样的：

```
┌─────────────┐     IPC 通道      ┌──────────────┐    SQL查询   ┌──────────┐
│   前端页面    │  ──────────────→  │  主进程       │  ────────→  │ todo.db  │
│  (React)    │  ←──────────────  │  (main.ts)   │  ←────────   │ (SQLite) │
│             │   返回 JSON 数据    │              │   返回结果    │          │
│  preload.ts │                   │ database.ts  │              │          │
│  暴露 API   │                   │ 执行真正的操作 │              │          │
└─────────────┘                   └──────────────┘              └──────────┘
```

具体来说：

1. **前端调用** `window.todoAPI.getLists()`（在 `preload.ts` 里暴露的 API）
2. **preload 脚本**通过 IPC（进程间通信）向主进程发消息，比如 `'db:getLists'`
3. **主进程**（`main.ts`）收到消息后，调用 `database.ts` 里的 `getLists()` 函数
4. **database.ts** 执行 SQL 语句 `SELECT * FROM task_lists`，把结果返回

## 实际代码长什么样？

**前端调用（React 组件里）：**

```javascript
// 获取所有列表
const lists = await window.todoAPI.getLists();

// 创建任务
await window.todoAPI.createTask({
  list_id: "xxx",
  title: "买菜",
});
```

**后端执行（database.ts）：**

```javascript
// 就是普通的 SQL 语句
db.prepare('SELECT * FROM task_lists ORDER BY position ASC').all();
db.prepare('INSERT INTO tasks (...) VALUES (...)').run(data);
```

## 初始化时自动做了什么？

应用启动时（`electron/main.ts` 第 99 行）会：

1. 自动创建 `todo.db` 文件（如果不存在）
2. 自动建表（如果表不存在）
3. 如果没有任何任务列表，自动创建一个默认的「任务」列表
4. 插入默认主题设置 `theme = 'light'`
5. 启用 WAL 模式（Write-Ahead Logging）提高并发性能
6. 启用外键约束（`foreign_keys = ON`），确保数据完整性

## 重复任务的处理

当完成一个设置了 `repeat_type` 的任务时，系统会自动创建一个新的重复任务，到期日期根据类型自动计算：

| 类型 | 下次日期 |
|------|----------|
| daily | +1 天 |
| weekly | +7 天 |
| monthly | +1 月 |
| yearly | +1 年 |

---

**总结一句话**：所有数据都在 `C:\Users\你的用户名\AppData\Roaming\Todo\todo.db` 这一个文件里，前端通过 Electron 的 IPC 机制让主进程帮忙读写，本质就是一个带前端界面的 SQLite 数据库。
